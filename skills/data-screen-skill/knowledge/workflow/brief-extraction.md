# 从对话提炼需求（Brief Extraction）

> 用户很少一次说清「行业、指标、数据源、分辨率、风格」。
> 你的任务不是追问，而是**先提炼、再假设、最后用一句话确认**。

## 1. 提炼 8 个维度

| # | 维度 | 要提取的内容 | 缺失时的默认 |
|---|---|---|---|
| 1 | 目标 | 给谁看？汇报/监控/展厅/网页？ | 领导汇报 |
| 2 | 行业 | 政务/交通/医疗/物流/金融/电商/能源… | 通用城市 |
| 3 | 对象 | 城市/区县/园区/门店/设备/车辆/企业 | 市级 |
| 4 | 指标 | KPI 名称、单位、口径、TOP N | 6 个通用指标 |
| 5 | 模块 | 必须有的图/表/地图/视频 | 按行业模板 |
| 6 | 数据 | 来源、字段、频率、鉴权 | mock + 预留 REST |
| 7 | 视觉 | 参考模板、主色、亮/暗、品牌 | T1 深蓝科技 |
| 8 | 约束 | 分辨率、浏览器、离线、内网、交付时间 | 1920×1080 / Chrome / 离线可用 |

## 2. 从对话里抓信号

| 用户说 | 推断 |
|---|---|
| 「给领导看」「汇报」「大屏演示」 | A1/A5，低密度，强结论，KPI 大 |
| 「指挥中心」「实时」「监控」 | A2/A3，高密度，状态灯，告警 |
| 「和 XX 系统对接」「接口」 | 需要 `data-contract` + adapter，先确认字段 |
| 「用我们公司的蓝色」「品牌色 #xxxxxx」 | 覆盖 `--accent`，其余保持主题 |
| 「LED」「拼接屏」「4K」 | S1 scale，安全边距 32–48px，避免细线 |
| 「投在会议室投影」 | 提高对比度，避免荧光色/深紫 |
| 「要能导出/打印」 | 需要浅色主题或单独打印样式 |
| 「先做个 demo」「占位数据」 | mock 数据 + 状态灯标「示例数据」 |
| 「参考这个截图/链接」 | 提取布局原型 + 配色，不要照抄内容 |

## 3. 假设策略

- **能推断就推断**，把假设写进 brief 的「假设」区，不要打断用户。
- **只有三种情况必须问**：
  1. 数据源结构完全未知，且用户要求「接真实数据」；
  2. 分辨率/屏幕比例非标准，且无法从上下文判断；
  3. 两个需求直接冲突（如「信息越多越好」+「只要 4 个指标」）。
- 提问 **≤ 3 个**，每个都给默认选项，例如：
  > 我按 1920×1080、深蓝科技风、6 个 KPI 先做；数据先用示例，接口按 REST 预留。如果你们是 4K 拼接屏或已有接口文档，告诉我即可调整。

## 4. 输出：SCREEN_BRIEF.md

```markdown

## 5. 视觉

- 主题：T1 深蓝科技；品牌色 #35d6ff
```

## 5. 工作示例

**用户原话**
> 我们区里要做个防汛指挥大屏，领导要看，最好能接气象和水利的数据，下周三演示。风格参考上次那个蓝色的。

**提炼**
- 目标：领导汇报 + 应急指挥 → A2/A1 混合
- 行业：政务/应急（防汛）
- 对象：区级
- 指标：降雨量、河道水位、泵站状态、转移人数、物资、告警
- 模块：区域地图（河流/泵站点位）、水位趋势、降雨预报、告警列表、物资/队伍
- 数据：气象 + 水利接口（未知字段）→ 先 mock，预留 REST + transform
- 视觉：深蓝科技（T1），参考 general-blue
- 约束：下周三演示 → 先出可演示版本，接口后补

**只需问 1 个问题**
> 水利/气象接口现在有文档吗？没有的话我先用示例数据 + REST 预留，演示不受影响。

## 6. 冲突处理优先级

当需求冲突时，按此顺序取舍：

1. **可读性** > 信息量（看不清楚 = 没做）
2. **真实性** > 视觉冲击（不编造业务数字）
3. **主结论** > 模块数量（删掉不影响结论的图）
4. **稳定运行** > 炫技动效（演示不能崩）
5. **客户指定风格** > 你的审美偏好

## 7. 不要做的事

- ❌ 用户说「随便做一个」，你就随机选行业和指标 → 先给一个通用城市模板并说明假设
- ❌ 用户没给数据，你却写出「2025 年 GDP 增长 8.3%」这种像真的数字 → 必须标示例
- ❌ 一次问 10 个问题 → 用户会放弃
- ❌ 把 brief 写成 3000 字方案书 → 一页以内，能直接指导写代码
