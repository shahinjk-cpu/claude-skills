# meta-ads

Turns ad information into in-situ mockups of Facebook and Instagram ads. You (the invoking agent) translate whatever you have into one `ads.json` file; the skill validates it, tells you what's missing for each placement, and renders.

The skill never reads spreadsheets, Excel files, briefs or web pages itself. Getting data out of those sources is your job, because only you know their shape (and sources like the Ad Library change over time). `SPEC.md` tells you exactly what to produce.

## Libraries

Ads are kept in **libraries**: named, persistent sets of ads, each in its own folder, that the user switches between in the viewer. Typical libraries are "My drafts", one per competitor ("Acme competitors"), or one per campaign. All libraries sit in one library root, `./meta-ads/` in your working directory:

```
meta-ads/
  index.html          generated home page listing every library (open this to pick one)
  libraries.js        generated list of libraries; its presence marks the root
  <library>/          one folder per library, named by library.py (lowercase, hyphens)
    ads.json          the library's spec. You and the user edit this; it's the source of truth.
    assets/           the library's source images and videos. Paths in ads.json point here (assets/hero.jpg).
    inventory.*       written by check.py
    viewer/           generated by render.py (index.html, data.js, media/, embed/, summary.json, png/). Safe to delete; re-render rebuilds it.
    exports/          files made to send: share files (.html), decks (.pdf, .pptx, .deck.json)
```

- **Which library?** If the user names one, use it. Otherwise run `python "${CLAUDE_SKILL_DIR}/scripts/library.py" list` and ask which to add to, or whether to start a new one. Don't mix unrelated sets of ads in one library just because it exists. One library can hold several brands (your drafts next to a competitor's), so put ads the user wants to compare side by side in the same library.
- **New library**: `python "${CLAUDE_SKILL_DIR}/scripts/library.py" new "Acme competitors"`. It creates the root if needed, `meta-ads/acme-competitors/` and its `assets/`. Then write `ads.json` there, with `campaign.name` set to the library's display name.
- **Add to or update a library**: edit its `ads.json` (append ads, swap placeholders for real creative), save any new media into its `assets/`, then check and render it again. The viewer updates in place.
- **Rename or remove**: the display name is `campaign.name` (edit it and re-render). To remove a library, delete its folder (after confirming with the user), then run `library.py index` to update the home page. Do the same after renaming a folder by hand.
- **Bring in an older render** from `meta-ads-output/`: make a library, copy that folder's `ads.snapshot.json` into it as `ads.json` and its `media/` files into `assets/`, change `media/` to `assets/` in the paths, then render.
- Use `--root DIR` with library.py only when the user wants the libraries somewhere else. render.py finds the root on its own from where `ads.json` sits.

## Steps

1. **Read `${CLAUDE_SKILL_DIR}/SPEC.md`** before writing anything. It defines every field, the shared-media rule, placeholders for missing creative, placement IDs, CTA codes, and a glossary mapping common source column names to spec fields. Complete examples are in `${CLAUDE_SKILL_DIR}/assets/examples/`.

2. **Write the library's `ads.json`** from the information you have (pick or create the library first; see Libraries above).
   - List each unique image/video once under `media` and reference it by ID from every ad that uses it. Ads with no creative yet get a `placeholder` media entry describing the intended image.
   - Give every brand an `avatar`: the page's real profile picture (see SPEC.md §4 for where to find it), or, only if you can't get it, an explicit 1:1 `placeholder`. A missing avatar is an error.
   - Copy text verbatim. Leave out what you don't know instead of inventing it; the check reports gaps.
   - Save remote media (especially Meta CDN links, which expire within days) into the library's `assets/` folder and point `src` at them.

3. **Check**: `python "${CLAUDE_SKILL_DIR}/scripts/check.py" ads.json`
   Fix all errors. Then look at the summary, `unlock` list and `shopping_list` (in `inventory.json` / `inventory.md`). If something important is missing (copy, a 9:16 version, an avatar), ask the user whether to supply it or render with placeholders now. Placeholders are a valid choice: the user may want to judge copy before creatives exist.

4. **Render**: `python "${CLAUDE_SKILL_DIR}/scripts/render.py" ads.json`
   For a library's `ads.json`, the viewer goes to `<library>/viewer/` and the root's home page and library list are refreshed. Re-rendering updates the same folder; stored media is reused.
   A spec that isn't in a library (a one-off check, the bundled examples) renders to `./meta-ads-output/<campaign>-<date>/` in your working directory, with an `ads.snapshot.json` copy of the spec, and no Library menu. Use `--out DIR` only if the user asks for another location.

5. **PNGs (when useful)**: `python "${CLAUDE_SKILL_DIR}/scripts/export_png.py" <output folder> [--ads A1,A2] [--placements ig_reels,fb_feed_mobile] [--dark] [--safe] [--limits] [--badges] [--all-cards]`
   Default is the clean in-situ view. `--safe`, `--limits` and `--badges` add review overlays and name files `__review`. Scope the export when there are many ads: 100 ads × 15 placements is 1,500 images.

6. **Export (when asked)**. Everything goes to the library's `exports/` folder. Never upload or post the results yourself; hand the files to the user.
   - **Single file:** `python "${CLAUDE_SKILL_DIR}/scripts/share.py" <viewer folder> [--ads A1,A2]` writes one self-contained `.html` that opens offline with no other files, for email, Slack or a shared drive. Videos become their cover frame, since the copy is for judging layout, not playback. Images are scaled down unless `--full-res` is given. Use `--ads` for a subset, especially if it reports more than 20 MB.
   - **PDF or PowerPoint deck:** `python "${CLAUDE_SKILL_DIR}/scripts/deck.py" quick --library <library folder> --format pdf,pptx --layout concept|lineup|versus [--placements fb_feed_mobile,ig_feed,ig_reels] [--ads A1,A2] [--title "..."] [--subtitle "..."] [--dark]`. `--dark` draws the mockups in dark mode; the viewer adds it to its request when the user has dark mode on.
     - `concept` makes one slide per ad, in up to three placements.
     - `lineup` puts up to four ads per slide in the first placement.
     - `versus` needs ads from exactly two brands and sets them against each other in the first placement.
     - Every deck gets a cover and a closing "about these mockups" slide. It also gets a `.deck.json` beside it: edit titles, order or `notes` there and run `deck.py build <file>.deck.json`.
     - PowerPoint needs python-pptx. If it's missing, the PDF is still made and the script prints where to get it.
     - Open the PDF and look at it before handing it over.
   - **Requests pasted from the viewer:** the Export menu gives the user a request such as *Export the "X" mockups as a PDF with the meta-ads skill: deck.py quick --library "D:/…/meta-ads/x" --format pdf --layout concept --placements … --ads … --title "…"*. Run exactly that command with the skill's script path, then give the user the output paths.

7. **Present**: give the user the path to the library's `viewer/index.html` (it opens offline by double-click), mention `meta-ads/index.html` when there's more than one library, and summarize the inventory: how many mockups are actual or simulated, and the top unlocks.

## What the user gets in the viewer

- **Library menu** (top left, when there are two or more rendered libraries): switches library and keeps the current view and overlays. "All libraries" (shown in any library's viewer) opens the home page, which shows each library's ads, brands, counts and last update.
- **Select ads** (top right): puts a checkbox on each ad (in Compare ads, Overview, and by the Ad picker in single-ad views). The selection is stored per library in the browser.
- **Export menu** (top right): the user chooses File, PDF or PowerPoint, which ads (this one, all shown, or selected) and the slide layout. **File** saves the single-file copy directly from the browser, using the scaled images render.py writes to `viewer/embed/`; no request to you is needed. **PDF** builds the same deck as deck.py in the browser (live mockups, not screenshots) and opens the print window, where the user picks Save as PDF; it can also produce a request to you. **PowerPoint** writes the .pptx in the browser (mockups drawn to JPEG pictures from `viewer/embed/`, editable text, ad text in the speaker notes) and saves it; it too can produce a request to you (see step 6). An older render without `embed/` gives only the request. The browser's deck layout and PowerPoint writer are JavaScript copies of deck.py's: a change to one needs the same change in the other. Three differences are deliberate: the browser's PowerPoint uses JPEG pictures (photos), exact line spacing (to match the PDF) and letter-spaced capital labels. Decks use the viewer's current light or dark mode for the mockups. It lists files already in `exports/` (as does the home page), each with Open (a new tab, or PowerPoint through Office's `ms-powerpoint:` link) and Show folder (the browser's folder listing). If an older render has no `embed/`, File falls back to a request; re-rendering fixes it.
- **Views**: Feed preview (default; one ad between ordinary posts, scrollable phone or story sequence) · Compare ads (every ad in one placement, side by side) · All placements (one ad everywhere, grouped Facebook phone / Instagram / Facebook desktop) · Overview (every ad × placement grid coloured by status, optional thumbnails). ‹ › or the arrow keys step through ads; Filter narrows by group, brand or status.
- **Overlays menu**: Stories and Reels safe areas, where text gets cut off (chars vs recommendation), why it's simulated, phone frame. Dark mode has its own button at the top right, and zoom its own − / + control. "What's this?" explains actual vs simulated.
- Videos play, carousels swipe, "See more" expands. Every view is a URL hash, so a link to a specific view can be shared alongside the folder. Settings (view, placement, overlays, dark mode, zoom) are remembered in the browser and carry across libraries; the last ad and filters are remembered per library.

## Rules for using the output

- Mockups imitate Facebook and Instagram UI and may contain other brands' ads. Keep them local: don't publish the viewer or PNGs as an Artifact, upload them to a hosting service, or post them anywhere unless the user explicitly asks and understands that.
- The mockups are close approximations of the current apps, drawn by hand in HTML/CSS. They have not been compared pixel-for-pixel against real ads, fonts fall back to the OS's system font, and some fallback behaviours are assumed (see `references/placements.md`). Present them as realistic previews, not as Meta's own rendering.
- "Simulated" means the renderer applied a fallback (crop, padded fill, placeholder creative or placeholder identity). Say so when presenting; don't present a simulated mockup as exactly what Meta will show.
- Placement rules are dated (`assets/placements.json`, `version_date`). `references/placements.md` lists sources and which behaviours are assumptions. If the user asks why something looks the way it does, read that file.

## Files

| Path | Purpose |
|---|---|
| `SPEC.md` | The ads.json contract. Read first. |
| `assets/examples/*.json` | Valid example specs (`showcase.json`: every format; `copy-first.json`: placeholders only) |

| `assets/placements.json` | Placement rules, ratios, text limits, safe zones, CTA labels |
| `assets/viewer.html` | The viewer (copied into each output) |
| `assets/libraries.html` | The library home page (copied to `meta-ads/index.html`) |

| `scripts/render.py` | Build the viewer (a library's `viewer/`, or a dated output folder) |
| `scripts/library.py` | Create, list and re-index libraries |
| `scripts/share.py` | Single-file copy of a viewer to send to someone |
| `scripts/deck.py` | Designed PDF and PowerPoint decks from the mockups |
| `scripts/export_png.py` | Headless Chrome/Edge PNG export |
| `scripts/sync_spec.py` | Regenerate SPEC tables after editing placements.json |
| `references/placements.md` | Sources, assumptions, fidelity notes, maintenance |

Requirements: Python 3.9+ with Pillow; ffmpeg/ffprobe for video measuring and posters; Chrome or Edge for PNG and PDF export (pass `--browser PATH` if it isn't found); python-pptx for PowerPoint export only.
